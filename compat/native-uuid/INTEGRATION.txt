Contracts:
- guid_t is exactly 16 bytes with alignment 1. Anonymous byte-array aliases b
  and guid_bytes both start at offset 0. Existing native GUID_INIT and ACPI
  raw 16-byte buffer users retain the same ABI. Linux callers have their real
  byte-array member, not a declaration-only or native struct-uuid replacement.
- netbsd_linux_uuid_t is a separate 16-byte/alignment-1 type. Native libuuid's
  uuid_t and uuid_equal declarations remain intact; tested in the same TU.
- GUID_INIT emits little-endian first three numeric fields; UUID_INIT emits
  big-endian. Copy/import/export transfer exactly 16 bytes without conversion.
- Full-byte equality, zero/null constants and endian index arrays are real.
- Parsing follows the frozen order and returns -EINVAL without touching output
  on invalid syntax. Validation preserves native and frozen first-36-byte
  semantics, including uppercase, fixed 36-byte input and accepted suffixes.
- Generation fills all 16 bytes from real native cprng_strong(kern_cprng,...,0)
  and applies version-4 bits at GUID byte 7 / UUID byte 6 and variant at byte 8.
  No time/PID/counter seed, fabricated bytes, no-op or fallback RNG is used.
- Exact native subr_cprng.c guarantees a full-length fill, permits thread/soft
  interrupt contexts and rejects hard interrupts. Required selected MST calls
  run after a reply wait or under the resume mutex; their source is recorded in
  generation-selected-context.json. Full Linux hard-IRQ generation parity OPEN.
- Native ACPI definitions originally used u64, while their native prototypes
  use uint64_t. Imported Linux u64 is unsigned long long and native uint64_t is
  unsigned long on HP, exposing a genuine C type mismatch. The six parameter
  spellings now match the native API; values, layout and ACPI algorithm unchanged.
