Lifetime and synchronization:
- Raw queue lock is IPL_HIGH; native CV interlock is separate IPL_VM.
- Only worker consumer takes sleep interlock then raw queue lock. IRQ producers
   schedule an MPSAFE CLOCK softint under raw lock. Notifier only takes sleep
   interlock; it cannot run through the condition-to-cv_wait handoff unnoticed.
- Generic task lt_lock protects private lt_kthread backend publication/lifetime.
   Shared wake only takes raw task -> raw worker and schedules notifiers.
- Stop/park first publish flags and wake native private/worker CVs, then release
   native interlock and invoke real linux_wake_up_process for common task CV.
  Private kt_lock is still held; wake has no reverse kt_lock/sleep acquisition.
- The worker publishes TASK_INTERRUPTIBLE before checking the native queue
  predicate, TASK_RUNNING after dequeue/exit, and TASK_PARKED during parkme.
  State setters run without the worker raw lock, avoiding worker -> task raw
  inversion. Generic idle-worker wake now reports the sleeping state correctly.
- Work callbacks execute outside worker locks. Worker never dereferences a work
   item after invoking it; callbacks may free their own unqueued work.
- Marker insertion gives snapshot flush ordering. Cancellation count blocks
   self-requeue until every concurrent canceler completes.
- Destroy closes queue, unparks, drains accepted immediate work, stops/joins native
   MUSTJOIN LWP, disestablishes notifier, and frees native CV/locks/worker.
- Queue/cancel/flush callers retain worker and work lifetime; they must quiesce
   new calls before freeing the worker, as required by Linux's contract.

Known limits, not stubbed support:
- Worker creation flags other than 0 return EOPNOTSUPP.
- Delayed workers, CPU/NUMA affinity and freezer support remain OPEN.
- Generic modern three-argument kthread_run and other task/PID/mm/IO APIs are
   outside this worker patch. Legacy five-argument native run remains available.
- Fatal-only task sleeps, complete task boundary attachment, arbitrary-context
   last task-reference release and module unload drain remain scheduler gates.
- Native kernel scheduler execution and HP GPU/KMS/RTL hardware acceptance OPEN.
