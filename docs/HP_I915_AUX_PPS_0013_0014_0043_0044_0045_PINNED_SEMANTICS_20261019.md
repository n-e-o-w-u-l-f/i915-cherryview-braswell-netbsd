## New lock-scope portability gap (independent from existing 0045 review)

Pinned NetBSD `intel_dp.c:1345–1528` executes **every** `intel_dp_aux_xfer()` with `aux_wakeref = intel_display_power_get(i915, aux_domain)` followed by **unconditional** `pps_wakeref = pps_lock(intel_dp)`; the same function releases with `pps_unlock` and then async AUX-domain put. `pps_lock():724–755` itself acquires an **additional AUX power-domain reference before `pps_mutex`**. `edp_panel_vdd_on():2704–2725` asserts that the mutex is held **before** its early return for non-eDP. This means simply copying new Linux's conditional PPS locking into the old NetBSD caller is **not safe** without also adjusting the non-eDP helper paths and balancing both wakerefs.

Pinned Linux `intel_dp_aux.c:258–310` instead conditionally runs `intel_pps_lock(intel_dp)` for **eDP on any platform OR Valleyview/Cherryview including non-eDP**, because the latter have pipe-instance PPS shared with other paths. New Linux also has an explicit `intel_digital_port_connected_locked` non-eDP guard and different power/ref tracking. Thus **an unconditional→conditional lock change without full source and ABI review would be a regression risk, not a verified optimization**.

The differing NetBSD/Linux power and lock ownership are now identified as a specific review target, not automatically closed as one of the 300 pending semantic rows. In particular:
- Ensure non-eDP calls do not reach `edp_panel_vdd_on()` without the expected lock; the assertion occurs before the `!intel_dp_is_edp()` early return.
- Preserve `AUX power get → PPS mutex → AUX hardware I/O → PPS unlock → AUX power put` for existing 0013/0014/0043 safety. Never hold PPS mutex across short-HPD dispatch, which may enter the AUX path recursively.
- Do not equate the NetBSD `pm_runtime_get_if_in_use` compatibility stub's return 1 with an active runtime-PM ownership lease.
