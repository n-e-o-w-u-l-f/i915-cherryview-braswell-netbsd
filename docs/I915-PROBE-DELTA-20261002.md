## Implemented and verified within this audit: patch 0007

`patches/0007-i915-early-probe-resource-unwind-netbsd11.patch` changes
the failure after `i915_workqueues_init` from a direct return to
`goto err_early`. The workqueue initializer already frees its own partial
workqueue allocations on failure; jumping **after**
`i915_workqueues_cleanup` avoids a double cleanup. All early-probe
failure paths after sideband QoS registration now also call
`pm_qos_remove_request(&dev_priv->sb_qos)` before destroying locks and
uncore state. This matches the existing late-release ownership order.

- `tools/generate_early_probe_unwind_patch.py` checks the exact frozen NetBSD
  commit, unchanged input bytes and unique source anchors.
- `tests/test_early_probe_unwind.py` compiles the **actual transformed
  `i915_driver_early_probe` body** under strict host C11 warnings/errors.
  Failure injection covers workqueue allocation, VLV S0ix allocation,
  power-domain initialization and successful initialization.
- `git apply --check` succeeds against both the clean frozen NetBSD tree and
  the separate, preserved six-edit overlay. Generator output and the published
  patch have matching bytes.
- Tests establish isolated cleanup control-flow semantics and patch
  applicability only. A native NetBSD i915 object build, whole-driver
  integration and hardware validation remain open.
